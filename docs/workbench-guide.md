## 画布与节点

编辑页面以铺满工作区的画布为主，节点库和配置面板按需浮动展开；运行记录与执行详情在独立页面查看。

1. 点击画布右上角「添加节点」展开节点库，点击节点添加后节点库自动收起；支持按名称或功能搜索和分类浏览，底部「刷新节点库」会重新扫描 `nodes/`。节点库展开不会缩小画布，Esc 可以关闭浮动面板。
2. 在画布中连接节点端口，例如把 `手动触发.success` 连接到后续节点输入。
3. 点击节点后，在右侧配置面板填写参数。
4. 拖动节点调整位置，位置会随工作流保存。

配置面板有两个标签页：

- **配置**：按节点声明的表单填写参数，可修改「节点名称」（工作流自己的显示标题，会显示在画布和运行日志中，不修改 Python 节点类型或节点配置），也可以删除节点。
- **运行数据**：查看该节点最近一次运行的输入、输出和错误。

**循环体**：`遍历循环`、`条件循环` 等节点带循环体。点击节点卡片或配置面板中的「编辑循环体」进入循环体画布，支持多层嵌套；画布顶部面包屑可返回上层或主流程。循环体内的节点、连线和运行事件通过 `scope` 归属到所属循环，运行详情会显示这条路径。

顶部工具栏提供：工作流名称输入、保存状态（已保存 / 未保存 / 正在保存）、保存按钮、运行按钮，以及「运行记录」「工作流」和「资源」导航入口。

## 保存与运行

- 点击「保存」提交当前画布。**没有自动保存，也没有 `Ctrl+S`**，请用顶部按钮保存。
- **运行不会自动保存**：点击「运行」用服务器上已保存的版本创建运行，未保存的画布改动不会进入本次运行。修改后先保存再运行。
- 运行创建后，顶部状态和画布节点跟踪执行状态；点击顶部状态或「运行记录」进入独立结果页面，编辑页不再显示底部结果面板。

**保存失败会明确提示**：

- 右上角弹出错误提示，顶部保存状态变为红色「保存失败」，悬停可看到完整原因。
- 工作流上方出现提示条，显示原因并提供操作：
  - **版本冲突**（服务器版本已被其他操作更新，返回 `409 workflow_version_conflict`）：「重新加载服务器版本」会在二次确认后放弃本地修改并加载服务器最新版本；「另存为副本」把当前画布保存为新的未发布副本。
  - **其他失败**（后端不可达、超时、校验失败等）：「重试保存」。
- 失败后画布仍标记为未保存，「保存」按钮保持可用，可以直接重试。冲突响应格式见[服务端行为参考](platform-behavior.md#版本发布与回滚)。

**导入导出**：在「工作流」页面中可把工作流导出为 JSON 文件，也可导入此前导出的文件或兼容的裸工作流 JSON。导出的是原始工作流文档；导入会清空 `id` 作为新工作流保存，重名时追加「(导入)」后缀，不覆盖已有工作流。「工作流」页面还提供新建、打开、删除，并显示每个工作流的版本号与最近一次运行状态。

## 运行结果

顶部「运行记录」打开当前工作流的运行页面。左侧历史每页 20 条，显示触发方式、状态、版本、短 ID 和时间，支持状态筛选、翻页与刷新；右侧展示选中运行的详情。切换页面不会停止状态跟踪，返回编辑器保留未保存草稿。

- **流程图**：读取该次运行记录的工作流版本，以只读画布展示节点状态和执行路径。支持平移、缩放、进入循环体；点击节点查看输入、输出、日志和原始事件。禁止拖动节点、修改配置、创建或删除连线。历史版本不可用时明确提示，仍可查看事件。
- **执行详情**：列出该次运行的全部事件。点击事件显示输出、输入、日志和原始数据，并可复制 JSON；切换回流程图可以定位对应节点。查看历史记录不修改编辑草稿。
- **逐条结果**：当运行产生了批量记录时（例如循环体内的 `记录测试结果`），可切换到该标签查看总条数、成功、失败、成功率和逐条明细，支持按成功/失败筛选与分页；点击某条结果可查看来源数据、完整记录与实际响应。
- HTTP 响应会以结构化方式展示：状态码、内容类型、响应大小、响应头与响应体。

**运行状态**：

- 工作流：队列中、运行中、已完成、失败、已取消。
- 节点：等待、运行中、成功、失败、已处理、已跳过、已取消。

## 子工作流组合

已保存的工作流可以像普通节点一样被同步调用：

1. 新建一个被调用工作流，并以唯一的 `工作流触发` 节点作为根节点。
2. 将输入接到后续节点；调用方传入的数据会从该节点的 `输入` 端口输出。手动运行被调用工作流时，输入为空对象。
3. 在需要把数据交还调用方的位置连接 `工作流返回` 节点。
4. 在调用方添加 `执行工作流` 节点，在右侧选择已保存的目标工作流，并连接它的输入、结果或错误端口。

`执行工作流` 会等待子工作流结束后才继续下游；未使用 `工作流返回` 时会返回空对象。直接或间接递归调用会在创建子运行前被拒绝。子工作流继承父运行的取消请求和剩余全局超时，因此不能在父运行结束后继续执行。子工作流失败会作为调用节点的普通失败处理。当前不提供异步后台调用。

运行记录支持父运行和来源节点字段，子运行详情可通过 `GET /api/runs/{id}` 读取。

## Webhook 触发

`Webhook 触发`是面向外部系统的通用触发器。

1. 为节点配置请求方法和路径，例如 `POST` 与 `hooks/orders`。
2. 节点输出包含 `method`、`path`、`headers`、`query` 和 `body`，后续节点可用表达式读取这些字段。
3. 需要自定义响应时，在下游连接 `Webhook 响应` 节点：它的输入成为 JSON 响应体，配置可设置状态码和响应头。一个请求只能实际设置一次响应，该节点不能用于手动运行或子工作流；未连接时返回运行记录和工作流输出的兼容响应。
4. **对外可用需要先投入生产**：工作台不提供发布入口，需要调用 `POST /api/workflows/{id}/activation`（见[服务端行为参考](platform-behavior.md#版本发布与回滚)）。在此之前，可用调试地址验证。

约定：

- 同一个请求方法和路径只能绑定一个已保存工作流。
- Webhook 触发器必须是入口节点，不能连接上游；同一工作流内不能重复配置相同方法和路径。
- 一个工作流可以有多个 Webhook 触发器，但单次请求只执行匹配入口及其下游。
- 「响应方式」默认为 `等待工作流完成`，适合把处理结果直接返回给调用方；`立即确认，后台执行` 会立即返回 `202 Accepted`、运行 ID 与 `Location: /api/runs/<运行 ID>`，随后由统一队列后台执行，该模式不能连接 `Webhook 响应` 节点。流式响应未提供。
- 「访问保护」可选择 `HTTP 请求头` 凭据（校验请求头名称与值，例如 `X-Webhook-Token`）或 `Webhook HMAC-SHA256 签名` 凭据（共享签名密钥与第三方发送签名的请求头名称，例如 `X-Hub-Signature-256`；平台对原始请求体计算 HMAC-SHA256，接受 `sha256=<十六进制签名>` 或裸十六进制签名）。签名头与固定验证头都会在运行输入、日志与详情中脱敏显示。

**调试地址** `POST /webhooks-test/<工作流 ID>/<path>` 精确调用最近保存的草稿版本，即使尚未发布，也不会执行未保存的画布改动；它使用与生产地址相同的请求头验证规则。调试监听通过 `webhook-test/listen` 接口启停，两分钟后过期并在收到一条请求后自动结束。

## 定时触发

`定时触发`用于按固定间隔自动执行工作流。

1. 配置「间隔秒数」（10 秒到 7 天），必须是入口节点，不能有上游连线。
2. 保存后需要调用 `POST /api/workflows/{id}/activation` 投入生产，服务端才会开始调度。
3. 每个到期的周期都会创建运行并交给统一队列，慢任务是否允许叠加由「运行并发」上限决定。
4. 触发数据包含 `trigger: "schedule"` 与 `scheduled_at`；下次执行时间持久化在 SQLite，服务重启后继续使用原有时间。

生产版本的启停状态、Webhook 绑定和定时器下次执行时间可通过 `GET /api/workflows/{id}/triggers` 读取。

## 表达式与变量

表达式使用 `{{ ... }}` 形式引用运行时数据：

```text
{{ vars.baseUrl }}
{{ project.baseUrl }}
{{ loop.item.username }}
{{ nodes.request.outputs.success.status_code }}
{{ variables.token }}
```

| 前缀 | 含义 |
| --- | --- |
| `project` | 项目级共享配置（「资源 → 项目变量」或运行环境中维护），适合多个工作流共用的接口基址、环境名和默认参数。每次创建运行都会固化为运行快照。 |
| `vars` | 单个工作流在文档 `settings.variables` 中维护的固定配置。 |
| `nodes` | 上游节点的输出，例如 `{{ nodes.request.outputs.success.status_code }}`。 |
| `loop` | 循环体中的当前项，例如 `{{ loop.item.username }}`。 |
| `variables` | 运行过程中由节点写入的变量。 |

「资源 → 项目变量」可以新建和删除变量；修改变量名或值需要调用 `PATCH /api/project-variables/{name}`。工作台不提供表达式静态校验，保存与运行时由服务端校验语法。

令牌、密码和固定鉴权头请放在「凭据管理」中，不要写入项目变量或工作流变量。

## 运行环境

「资源 → 运行环境」列出已有环境及其变量。每个环境保存一组 JSON 变量，工作流表达式通过 `{{ project.xxx }}` 读取当前环境的值，因此不需要为每个环境复制画布或修改节点配置。

环境还可以建立「工作流凭据 → 环境实际凭据」的同类型映射：节点中固定引用「默认 HTTP 令牌」，在测试环境映射为「测试 HTTP 令牌」，发布环境映射为「生产 HTTP 令牌」，映射只保存凭据 ID，不保存或展示秘密值。

创建、修改和删除环境使用 `/api/project-environments` 接口；生产触发使用已发布版本所选的环境，手动运行可在创建运行时通过 `environment_id` 临时指定。每条运行都会记录环境 ID、名称、变量快照和凭据映射快照，环境后续修改不会改变已有运行。

## 凭据管理

「资源 → 凭据管理」用于维护仅本机可用的连接凭据。

- 内置支持 Bearer 令牌、Basic 认证和固定请求头；本地节点包还可以声明自己的凭据类型。
- 凭据在 Windows 上使用当前登录用户的 DPAPI 加密后写入 SQLite，工作流只保存凭据 ID 引用。
- 在 HTTP 请求节点的「认证凭据」中选择已创建的凭据即可。请求头的覆盖顺序为：凭据注入 < 节点配置请求头 < 输入端口请求头。
- 凭据字段不会出现在列表、工作流导出、运行事件或运行详情中；编辑凭据时只有勾选「重新填写并替换凭据值」后才会写入新的秘密值。
- 编辑凭据时会显示引用它的工作流与节点，删除前请先确认引用情况。
- 此能力目前仅支持 Windows；其他平台会拒绝凭据写入而不会降级为明文存储。已有 `NODE_FLOW_SECRET_*` 环境变量仍可供 Python 节点兼容使用，但不会自动导入凭据库。
- 解密后的凭据字段只在当前根运行及其同步子工作流执行期间保留于运行级脱敏上下文；运行结束、失败或取消后立即释放，不同并发运行之间不共享凭据值。

「资源 → HTTP 配置档」用于复用 Base URL、公共请求头、HTTP 凭据和默认超时，仅 HTTP 请求节点会读取它。「资源 → 节点工作室」用于调整节点在画布和预览中的展示方式（端口显示名、卡片样式、摘要模板）。

## 测试自动化节点

内置节点已经覆盖常见测试工作流：

| 节点 | 用途 |
| --- | --- |
| `读取 CSV` | 读取 CSV 行和列，用于数据驱动测试。 |
| `遍历循环` | 对 CSV 行或任意列表逐项执行循环体。 |
| `HTTP 请求` | 发送接口请求并输出状态码、响应头和响应体。 |
| `状态码断言`、`相等断言`、`包含断言` | 判断接口响应是否符合预期。 |
| `记录测试结果`、`测试汇总`、`写入测试报告` | 收集断言结果并写出报告。 |

一个典型流程是：`手动触发 -> 读取 CSV -> 遍历循环`，在循环体里执行 `HTTP 请求 -> 断言 -> 记录测试结果`，循环结束后执行 `测试汇总 -> 写入测试报告`。

**单接口状态码断言**：

1. 连接 `手动触发 -> HTTP 请求 -> 状态码断言 -> 记录测试结果 -> 测试汇总 -> 写入测试报告`。
2. 在 `HTTP 请求` 节点填写请求方法和 URL。
3. 在 `状态码断言` 节点把实际状态码指向 HTTP 请求输出，例如 `{{ nodes.request.outputs.success.status_code }}`，并填写期望状态码，例如 `200`。
4. 在 `写入测试报告` 节点填写报告输出路径，例如 `reports/smoke-status.json`。

**CSV 参数化接口测试**：

1. 准备 CSV 文件，例如 `data/users.csv`，首行写列名，后续每行是一组测试数据。

   ```csv
   name,url
   node_types,http://127.0.0.1:8150/api/node-types
   health,http://127.0.0.1:8150/api/health
   ```

2. 连接 `读取 CSV -> 遍历循环`，并在循环体里连接 `HTTP 请求 -> 断言 -> 记录测试结果`。
3. 在 `读取 CSV` 节点填写文件路径，确认分隔符和表头设置。
4. 在 `遍历循环` 节点把循环输入指向 CSV 读取结果；循环体中的 HTTP 请求可用 `{{ loop.item.列名 }}` 引用当前行字段。
5. 循环结束后连接 `测试汇总 -> 写入测试报告`，运行完成后在「运行记录 → 执行详情 → 逐条结果」查看通过、失败和未知结果。

运行与排查：点击顶部「运行」创建运行（记得先保存），在「运行记录 → 执行详情」查看节点级事件，点击事件查看输入、输出、日志、错误和循环范围；也可在只读流程图中选择节点查看运行数据。

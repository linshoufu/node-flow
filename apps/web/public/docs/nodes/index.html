触发器

手动触发

manual.trigger

从配置中的 payload 产生初始数据，适合手动启动、调试和构造测试输入。

输出：初始数据分组：触发器

定时触发

schedule.trigger

按固定间隔自动启动已启用的工作流。首次保存或启用后会等待一个完整间隔，再创建新的运行记录。

  • 配置“间隔秒数”，范围为 10 秒到 7 天。
  • 定时触发必须作为入口节点，不能接收上游连线。
  • 同一工作流已有排队或运行中的实例时，会跳过本轮，避免并发重入。

工作流触发

workflow.trigger

作为被调用工作流的唯一入口，接收调用方传入的数据。手动运行时会提供空对象。

输出：调用输入分组：触发器

执行工作流

workflow.execute

同步调用一个已保存的工作流，等待它通过“工作流返回”节点给出结果。调用会继承取消请求和剩余超时。

输入：调用数据输出：结果、错误

工作流返回

workflow.return

把当前数据显式返回给调用方。未使用该节点的被调用工作流会返回空对象。

输入：结果输出：已返回

Webhook 触发

webhook.trigger

收到匹配方法和路径的 HTTP 请求后启动工作流，并输出请求方法、请求头、查询参数和请求体。

输出：请求数据分组：触发器

Webhook 响应

webhook.respond

为当前 Webhook 请求设置 JSON 响应体、响应状态码和响应头。一个请求只能实际设置一次响应。

输入：响应内容输出：已响应

网络

HTTP 请求

http.request

发送 HTTP 请求并输出状态码、响应头和响应体。请求体和请求头既可以来自配置，也可以来自输入端口。

输入：请求体、请求头输出：响应、错误

数据

读取 CSV

data.csv_read

读取 CSV 文件并输出 headers、rows、columns、row_count 和逐行数据项。数据项可直接连接到“逐项循环”。

输出：数据集、数据项、错误常用：loop.item.column_name

提取数据

data.extract

从输入对象中按路径提取一个值，适合把复杂响应整理成下游节点需要的字段。

输入：数据输出：提取值、错误

映射数据项

data.map_items

为每个输入数据项构造新的 JSON 值，同时保留来源配对和二进制元数据。配置中可用 {{ item.field_name }} 读取当前项，也可以组合成新的对象。

输入：数据项输出：数据项常用：item.field_name

筛选数据项

data.filter_items

读取每个数据项中的值并按比较方式保留匹配项。值表达式可使用 {{ item.field_name }}；支持相等、不相等、存在、为空和非空比较。

输入：数据项输出：匹配项常用：item.field_name

合并数据项

data.merge_items

把多个上游数据项流按到达顺序追加为一条流，适合在分支处理后重新汇合，或把多个数据来源交给同一个逐项循环。

输入：多路数据项输出：合并结果

命名汇聚

data.collect

为每条上游连线配置独立的输入端口名称，再输出一个以端口标识为键的对象。适合并行流程汇合后保留每个来源。

输入：可配置的具名端口输出：汇聚结果

控制流

逐项循环

control.each_item

接收标准数据项并逐项执行循环体。循环体内可用 {{ loop.item }} 访问当前项的 JSON 数据。

输入：数据项输出：完成、错误

遍历循环

control.foreach

对列表或 CSV 行逐项执行循环体。循环体内可用 {{ loop.item }} 引用当前项。

输入：循环输入输出：完成、错误

条件循环

control.while

在条件表达式为真时重复执行循环体，适合轮询或等待状态变化。建议设置合理的最大迭代数。

输入：循环输入输出：完成、达到上限、错误

条件分支

logic.if

根据条件表达式把数据路由到 true 或 false 输出端口。

输入：输入输出：为真、为假

路由分支

logic.switch

按配置的路由规则匹配输入值，并从对应的规则输出端口继续执行。每条规则的端口标识必须唯一，修改后会同步更新画布端口；未命中时走“未匹配”输出。

输入：输入输出：规则端口、未匹配配置：规则的端口标识、名称和匹配值

设置变量

logic.set_variable

写入运行时变量，供后续节点通过 {{ variables.name }} 引用。

输入：输入输出：变量

工具

转换数据

utility.transform

返回一个表达式或配置值，用于整理字段、构造下游 payload 或临时调试数据形状。

输入：输入输出：转换结果

记录日志

utility.log

向运行日志写入一条消息，并将输入透传给下游。适合调试长工作流。

输入：输入输出：继续

延迟等待

utility.delay

等待指定秒数后继续执行，常用于接口异步处理、重试前暂停或演示取消运行。

输入：输入输出：继续

断言

状态码断言

assert.status_code

检查 HTTP 响应状态码是否等于期望值。通过和失败会走不同输出端口。

输入：响应输出：通过、失败

相等断言

assert.equals

按路径读取实际值，并和期望值做相等比较。

输入：数据输出：通过、失败

包含断言

assert.contains

检查字符串、数组或对象值中是否包含期望内容。

输入：数据输出：通过、失败

测试报告

记录测试结果

test.record_result

记录一条断言结果，供后续汇总节点生成测试报告。

输入：断言结果输出：记录结果

测试汇总

test.summary

汇总运行过程中记录的测试结果，生成总数、通过数、失败数和明细。

输入：上游完成输出：汇总、失败汇总

写入测试报告

test.write_report

把测试报告写成 JSON 文件，适合本地归档或交给其它工具继续处理。

输入：报告输出：已写入、错误
